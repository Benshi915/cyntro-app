# LiveTime

הרשת שמחברת **אמנים**, **מקומות** ו**קהל**, להופעות חיות.
מקומות מוצאים אמנים, אמנים סוגרים הופעות בתנאים ברורים, והקהל יודע איפה מנגנים הערב.

## מה יש ב-MVP

| תחום | מה עובד |
|---|---|
| הרשמה ופרופילים | מייל + סיסמה, בחירת צד (אמן / מקום / קהל), פרופיל לכל צד: מחיר והרכב לאמן, קיבולת, ציוד, תקציב ומיקום על מפה למקום |
| גילוי | חיפוש אמנים ומקומות לפי שם, סגנון ועיר |
| מפה | הופעות ומקומות על מפת לילה (MapLibre + OpenFreeMap, בלי מפתח API) |
| פיד | "הערב", "בהמשך", סינון לפי עיר וסגנון, פוסטים ממי שאתם עוקבים אחריו |
| תוכן | פוסטים עם טקסט, תמונה ונגן YouTube / Spotify / SoundCloud |
| לייקים מותאמים | **הדרן 🔥** על פוסטים · **מגיע/ה / מעניין אותי** על אירועים · **תביאו אותם!**: ביקוש קהל לאמן לפי עיר (מוצג למקומות) · **שמירה** לרשימה קצרה |
| הצעות הופעה | בונה עסקה עם 6 מודלים כלכליים ותחזית חיה של כמה כל צד מקבל, הצעה נגדית, אישור, דחייה וביטול. אישור יוצר אירוע אוטומטית |
| צ'אט | שיחות 1:1 בזמן אמת (Supabase Realtime), עם כרטיסי הצעה בתוך השיחה |
| PWA | ניתן להתקנה על הטלפון |

### המודלים הכלכליים (`src/lib/deals.ts`)
מחיר קבוע · הכרטיסים לאמן · חלוקת קופה · הגבוה מביניהם (מינימום מובטח מול אחוז מהקופה) · קבוע + בונוס · כניסה חופשית + טיפים.
העמלות מוגדרות במקום אחד (`FEES`) כדי שאפשר יהיה לנסות תמחור אחר בשינוי של שורה.

## טכנולוגיה
Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · Supabase (Postgres, Auth, Storage, Realtime) · MapLibre.

כללי העסקה (מי רשאי לאשר, מעבר בין סטטוסים, יצירת האירוע) רצים בתוך בסיס הנתונים, בפונקציות `SECURITY DEFINER` עם RLS. כך הלקוח לא יכול לעקוף אותם.

## הרצה מקומית

```bash
npm install
cp .env.example .env.local   # למלא את פרטי Supabase
npm run dev
```

**בלי Supabase** האפליקציה רצה ב**מצב הדגמה**: מוצגים נתונים לדוגמה, ופעולות שכתיבה מחזירות הודעה שצריך לחבר את בסיס הנתונים.

## חיבור Supabase

1. פותחים פרויקט חדש ב-Supabase.
2. ב-**SQL Editor** מריצים את `supabase/migrations/0001_init.sql`. אחר כך, לנתוני דוגמה, מריצים את `supabase/seed.sql`.
3. ב-**Authentication → URL Configuration** מגדירים:
   - Site URL: כתובת האתר
   - Redirect URLs: `https://<הדומיין>/auth/callback`
4. ב-`.env.local`, או ב-Vercel, ממלאים `NEXT_PUBLIC_SUPABASE_URL` ו-`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. ה-anon key הישן עובד גם הוא.

> טיפ לבדיקות: אם מכבים את **Confirm email** ב-Authentication → Providers → Email, ההרשמה נכנסת ישר בלי לחכות למייל.

לעדכון נתוני הדוגמה: עורכים את `src/lib/demo-data.ts` ומריצים `node scripts/gen-seed.mts`.

## מבנה

```
src/app/(app)/        אפליקציה: feed, discover, map, p/[handle], events, messages, bookings, settings
src/app/(auth)/       כניסה והרשמה
src/app/onboarding/   יצירת פרופיל
src/app/actions.ts    כל פעולות הכתיבה (server actions)
src/lib/data.ts       שכבת הנתונים, עם fallback למצב הדגמה
src/lib/deals.ts      מודלים כלכליים, עמלות ותחזית
src/components/       UI, מפה, בונה עסקה, כרטיסים
supabase/             סכמה, RLS, פונקציות ונתוני דוגמה
```

## השלבים הבאים
1. **תשלומים**: סליקה ישראלית עם פיצול תשלומים (PayMe / Grow), נאמנות על הצעות שאושרו, מכירת כרטיסים וטיפים.
2. **חשבוניות**: הפקה אוטומטית (Morning / חשבונית ירוקה).
3. **ביקורות** אחרי הופעה (רק על עסקאות שנסגרו דרך הפלטפורמה).
4. **התראות** (Web Push ומייל) על הצעות, הודעות והופעות של מי שעוקבים אחריו.
5. **יומן זמינות** למקומות ולאמנים.
6. **ניהול**: אימות פרופילים, יצירת פרופילים ידנית ושיוכם לבעלים.
